# Video result storage (local)

When a provider reports success, the generation moves from `processing` to
`storing`; it is not marked successful and its quota is not finalized yet. The
worker obtains the provider's normalized result descriptor, streams it into
`backend/storage/videos/.tmp`, validates the stored bytes, and atomically
renames the file under the configured storage root. Only then does one database
transaction persist result metadata, finalize the reservation, move reserved
usage to used usage, clear the lease, and mark the generation `succeeded`.

The local store writes no provider URL to the database or API. Temporary names
are random, final keys are generated by the worker, traversal and symlink
escapes are rejected, and old temporary regular files can be removed with the
bounded cleanup service. An existing final file is validated and hashed before
retry finalization, covering a crash after rename and before the DB commit.

Accepted result types are MP4 (`ftyp`) and WebM (EBML), with an exact MIME
match, non-empty size, and `VIDEO_RESULT_MAX_BYTES` enforced while streaming.
HTML/JSON error pages and extension-only spoofing are rejected. There is no
whole-file buffering.

The Metis adapter alone fetches result URLs. It accepts only HTTPS result URLs,
rejects credentials and IP literals, restricts hosts to the configured allow
list (or the configured Metis host), revalidates redirects, sets a timeout and
size limit, and returns only safe errors. In test mode the Fake provider emits
an in-process MP4 stream; no real Metis request is made.

Temporary download/network failures keep the job in `storing`, retain its
reservation, release the lease, and use bounded exponential retry. Invalid
descriptors, invalid MIME/signature, oversize output, rejected URLs, and the
maximum retry count fail the job and release the reservation. Terminal jobs are
never re-stored or recharged.

Owners can retrieve a successful result at
`GET /api/video-generations/:generationId/content`. It supports `HEAD`, secure
inline/download disposition, and single-byte ranges (`200`, `206`, `416`) while
streaming only the requested range. The API read model contains internal content
URLs and safe metadata only; it never exposes keys, paths, URLs, or hashes.

Environment settings:

- `VIDEO_STORAGE_ROOT` (defaults to `backend/storage/videos`)
- `VIDEO_RESULT_MAX_BYTES` (default `104857600`)
- `VIDEO_RESULT_DOWNLOAD_TIMEOUT_MS` (default `60000`)
- `VIDEO_RESULT_MAX_REDIRECTS` (default `2`)
- `VIDEO_STORAGE_TEMP_MAX_AGE_MINUTES` (default `60`)
- `VIDEO_STORAGE_MAX_ATTEMPTS` (default `4`)
- `VIDEO_STORAGE_RETRY_BASE_DELAY_MS` / `VIDEO_STORAGE_RETRY_MAX_DELAY_MS`

Local disk is suitable for development only. Production can replace the storage
interface with an object-storage implementation while preserving validation,
transactional finalization, and the content authorization contract. Back up the
final storage root and database together. This implementation intentionally
made zero real Metis requests and does not deploy or contact a VPS.
